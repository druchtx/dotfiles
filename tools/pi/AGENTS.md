# Global Pi Rules

These are my default rules for Pi across projects.

- Keep responses concise and implementation-oriented.
- Read relevant local files and project instructions before proposing changes.
- Prefer small, reversible edits that match the existing project style.
- State assumptions, blockers, and verification steps directly.
- Do not scan unrelated directories unless the task requires it.
- Use the repository's existing commands and tooling when available.
- Run the narrowest relevant checks after making changes.
- Treat project-local `AGENTS.md` and `CLAUDE.md` instructions as authoritative for that project.
- Never expose or commit credentials, tokens, private keys, or local session data.
